Slide 8: The API is becoming the runtime.

More of the work once assembled in each client is moving behind the API: executing tools, reconstructing history, compacting context, and preparing searchable knowledge. OpenAI Responses illustrates the shift with built-in web/file search and server-side compaction; its vector stores automatically chunk, embed, and index uploaded files. Anthropic illustrates the same direction with server-executed web search, server-side compaction, and Messages threads. These are examples of a shared architectural direction, not identical feature sets.
Memory deserves its own boundary: long-term memory stores selected knowledge across sessions; compaction reduces active context; retrieval finds relevant content. Anthropic's Messages memory tool is explicitly client-executed: the application implements file operations and controls storage. That application can itself run on a server, but this is not Anthropic-hosted memory. Do not claim that Anthropic's Files API is equivalent to OpenAI vector stores or that both vendors supply every capability listed. Chunking and embedding are retrieval infrastructure, not necessarily tools the model calls directly.
A tool declaration still is not execution. A shell tool can run in a local harness or a remote harness container; a built-in search can run in the agentic server; the inference engine generates model output. Ask: who executes, who stores, and who supplies the next context? These are precisely the boundaries Agentic API lets us inspect and control on open infrastructure.

The API now owns more of the work between model calls.

Slide 19: What happens when the context fills up?

Explain that long tasks accumulate files, logs, tool call outputs, and intermediate plans. The next round has a finite context budget. Compaction spends an inference call to produce a smaller continuation window. Truncation simply discards content; summarization introduces its own risk of losing constraints or provenance. In vLLM Agentic API, the standalone compact endpoint returns retained user messages and a compaction item. The complete output array is the continuation input. The local implementation's field is named encrypted_content for wire compatibility, but the content is plaintext; it is not interoperable with OpenAI's encrypted checkpoints. Keep that distinction in a short note, then focus on the engineering question: what must survive for the next code change to remain correct? The two aligned plots are illustrative: active context rises to a trigger, then drops at compaction; task fidelity may recover if the checkpoint preserves constraints or decline if it loses them. Slide 23: From one machine to a Kubernetes fleet.

The point is independently scalable workloads, not a taxonomy of engines. In this gateway deployment, CPU-only Agentic API replicas hydrate item history from shared PostgreSQL, orchestrate inference rounds, and execute supported built-in tools or call external tool services. Kubernetes deploys separate CPU and GPU worker pools; it does not automatically choose the right scaling policy. llm-d routes model requests by load and cache locality. In a configured vLLM disaggregated deployment, GPU prefill workers compute the prompt KV cache and transfer it to GPU decode workers.
